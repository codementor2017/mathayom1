Step-by-Step Problem Solving with Algorithms

Big problems can feel overwhelming — but if you break them into smaller steps, they become easy to solve! In this lesson, you'll learn the skill of decomposition: breaking a complex problem into input, process, and output — then solving it one step at a time.

Warm-Up: The Big Problem

Here's a problem that sounds complicated at first:

🤔
"Calculate the average speed of a car that travels 3 different distances in 3 different times."

Where do we even start? Well — we don't solve it all at once. We break it into smaller steps.

Let's list the steps:

  1. What information do we input?
  2. What do we process with that information?
  3. What do we output?
💡
Key idea: Step-by-step problem solving means breaking a big problem into small, manageable steps. This is called decomposition.
What is Decomposition?
Definition
Decomposition = breaking a big problem into smaller steps, each of which is easier to solve.

Every problem we solve with a program has three parts:

📥

Input

What information do we have?

⚙️

Process

What steps do we take with that information?

📤

Output

What do we want to produce?

💡
Abstraction helps us here too. When breaking a problem into steps, we ignore non-essential details (like the car's color) and focus on what matters.

Example: Average Speed

Let's break down the "average speed" problem step by step.

Step 1 — Identify the input

  • distance1, time1
  • distance2, time2
  • distance3, time3

Step 2 — Identify the process

  • total_distance = distance1 + distance2 + distance3
  • total_time = time1 + time2 + time3
  • average_speed = total_distance ÷ total_time

Step 3 — Identify the output

  • Print average_speed

All together as pseudocode:

Pseudocode
START
  INPUT d1, t1, d2, t2, d3, t3
  total_d = d1 + d2 + d3
  total_t = t1 + t2 + t3
  avg_speed = total_d / total_t
  PRINT avg_speed
END
💡
Abstraction in action: We ignored non-essential details like the car's color or the driver's name. We only kept the numbers that matter.
From Pseudocode to Python

Now let's convert the pseudocode into real Python code:

Python Program
d1 = float(input("Distance 1: "))
t1 = float(input("Time 1: "))
d2 = float(input("Distance 2: "))
t2 = float(input("Time 2: "))
d3 = float(input("Distance 3: "))
t3 = float(input("Time 3: "))

total_d = d1 + d2 + d3
total_t = t1 + t2 + t3
avg_speed = total_d / total_t

print("Average speed =", avg_speed)

What if one time is zero?

If total_t = 0, the program will crash with a "division by zero" error. This is an edge case we need to handle.

Adding a check:

Improved Python
# (input the values)

total_d = d1 + d2 + d3
total_t = t1 + t2 + t3

if total_t == 0:
    print("Time cannot be zero!")
else:
    avg_speed = total_d / total_t
    print("Average speed =", avg_speed)

Guided Practice: From Problem to Code

Let's solve a new problem together: "Calculate the total resistance of three resistors in series."

Step 1 — Identify the input:

  • r1, r2, r3 (resistances in ohms)

Step 2 — Identify the process:

  • total_r = r1 + r2 + r3 (in a series circuit, resistances add up)

Step 3 — Identify the output:

  • Print total_r

Pseudocode:

Pseudocode
START
  INPUT r1, r2, r3
  total_r = r1 + r2 + r3
  PRINT total_r
END

Python code:

Python Program
r1 = float(input("Resistor 1 (ohms): "))
r2 = float(input("Resistor 2 (ohms): "))
r3 = float(input("Resistor 3 (ohms): "))
total_r = r1 + r2 + r3
print("Total resistance =", total_r, "ohms")

The Step-by-Step Method

Use these 5 steps for every math or science problem:

  1. Read the problem carefully.
    What is it really asking? What is the goal?
  2. Identify the input.
    What information do you have? What variables do you need?
  3. Identify the process.
    What calculations or comparisons do you need to make?
  4. Identify the output.
    What do you want to produce? A number? A decision? A chart?
  5. Write the algorithm.
    Use pseudocode first, then write the Python program.
💡
Why this method works: It takes a big, scary problem and turns it into small, clear steps. Each step is easy on its own — together they solve the whole problem.

Key Takeaway

Decomposition — breaking a big problem into smaller steps — is one of the most powerful skills in programming. Every problem has three parts: Input, Process, Output. Follow the 5-step method: read carefully, identify input, identify process, identify output, then write the algorithm. Always test with different inputs and handle edge cases like division by zero.
