Algorithms in Daily Life

Every day, you follow step-by-step instructions — brushing your teeth, making a sandwich, walking to school. These step-by-step instructions are called algorithms. In this lesson, you'll learn what makes a good algorithm and how to write one that anyone can follow.

100 minutes Clear Steps Sequence & Order Finite & Complete

Warm-Up: Sequence Game

Below are the steps for brushing your teeth — but they're all mixed up! Can you put them in the correct order?

  • Pick up toothbrush
  • Put toothpaste on toothbrush
  • Open mouth
  • Brush teeth for 2 minutes
  • Rinse mouth
  • Clean toothbrush
  • Put toothbrush away

The correct order is:

  1. Pick up toothbrush
  2. Put toothpaste on toothbrush
  3. Open mouth
  4. Brush teeth for 2 minutes
  5. Rinse mouth
  6. Clean toothbrush
  7. Put toothbrush away
💡
What if we change the order? If you "rinse mouth" before "put toothpaste on toothbrush," it wouldn't make sense. Order matters in algorithms!
What is an Algorithm?
Definition
An algorithm is a clear, ordered set of steps
to solve a problem or complete a task.

Every good algorithm has four properties:

🔍

Clear Steps

Each step is specific — no vague language like "walk a bit" or "cook for a while."

🛑

Finite

The algorithm has a clear end. It stops when the task is done.

🔢

Ordered

Steps follow a specific sequence. Changing the order breaks the algorithm.

✅

Produces a Result

When followed correctly, the algorithm solves the problem.

Everyday Examples of Algorithms

You already use algorithms all the time! Here are some examples:

Task Sample Steps
🍚 Cooking rice Wash rice → Add water → Turn on cooker → Wait → Serve
🧭 Walking to a friend's house Walk straight → Turn left → Cross road → Ring bell
💻 Logging into a computer Turn on → Enter username → Enter password → Press Enter
🍞 Making a sandwich Get bread → Add filling → Close → Cut → Serve
💡
Every algorithm uses abstraction — we only include the steps that matter, and skip the ones that don't (like "use a blue plate" or "hum a song").

Bad Algorithm vs Good Algorithm

Let's compare a bad algorithm and a good one for the same task:

❌ Bad Algorithm

"Cook rice. Eat."

What's missing? No steps in between! How do you cook rice? How long? How much water? This isn't a real algorithm.

✅ Good Algorithm

"Wash rice, add 2 cups water, cook for 20 minutes, serve."

Why it's good: Clear steps, specific amounts, ordered sequence, and a clear end result.

A good algorithm should be:

  • Specific — no vague words
  • Complete — no steps missing
  • Ordered — steps in the right sequence
  • Testable — someone else can follow it and succeed
Guided Practice: Making a Tuna Sandwich

Let's write the algorithm together for "Make a tuna sandwich."

  1. Wash hands. (Important for hygiene!)
  2. Take two slices of bread.
  3. Open the tuna can.
  4. Mix tuna with mayonnaise.
  5. Spread tuna on one slice of bread.
  6. Put the other slice on top.
  7. Cut the sandwich in half.
  8. Serve.

Now let's think about abstraction:

  • Which steps are essential? All of them! They're all necessary to make the sandwich.
  • Which details can be ignored?
💡
Essential: "Wash hands" — it protects your health.
Non-essential: "Use a blue plate" — the color doesn't affect whether the sandwich is made correctly.

Your Turn — Write a Daily Task Algorithm

Work in groups of 3–4 students. Choose one daily task below and write an algorithm with 6–10 clear steps.

🌅

Option A

Morning routine before school

📚

Option B

Going to the library to borrow a book

💻

Option C

Logging into a school computer

🌱

Option D

Watering a plant

🎒

Option E

Preparing a school bag

Your algorithm must include:

  • 6–10 clear steps
  • A clear beginning and end
  • Only essential steps (use abstraction!)
  • A list of 3 non-essential details you ignored

Then: Swap your algorithm with another group. Try to follow their algorithm exactly. Does it work? Are any steps unclear?

Activity — Test and Improve

When you swap algorithms with another group, write down:

  1. One step that was unclear or confusing.
  2. One step that seemed to be missing.
  3. One non-essential detail they correctly ignored.
  4. One suggestion to make their algorithm better.

Then, use their feedback to improve your own algorithm. Write down the changes you made.

💡
Remember: Testing an algorithm is how you find errors and improve it. Good programmers test their work — again and again.

Key Takeaway

An algorithm is a clear, ordered set of steps to solve a problem. Good algorithms have four properties: clear steps, finite (they end), ordered, and they produce a result. When you write an algorithm, use abstraction — include only the essential steps. Next lesson, you'll learn how to write algorithms in two special ways: pseudocode and flowcharts.

Homework

Part 1 — Write an algorithm for a household chore:

  • Choose one chore: washing dishes, sweeping the floor, feeding a pet, or similar.
  • Write an algorithm with 6–10 clear steps.
  • Include a beginning and an end.

Part 2 — Identify non-essential details:

  • Write down 3 non-essential details you deliberately ignored.
  • Explain why each one doesn't affect the task.

Part 3 — Test it:

  • Ask a family member to follow your algorithm exactly. Did they succeed?
  • Write down one improvement you would make.
