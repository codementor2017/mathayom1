Pseudocode and Flowcharts

In Lesson 4, you learned to write algorithms as simple step lists. But there are two other powerful ways to write algorithms: pseudocode (code-like language) and flowcharts (pictures with symbols). Both help you communicate your algorithm clearly to anyone — including future programmers.

Quick Review from Lesson 4

Remember: an algorithm is a clear, ordered set of steps to solve a problem.

Every good algorithm has four properties:

  • Clear steps — no vague language
  • Finite — has a clear end
  • Ordered — steps in the right sequence
  • Produces a result — solves the problem
💡
Today's focus: How do we write down an algorithm so it's easy to understand, share, and turn into code?
What is Pseudocode?

Pseudocode is a way of writing an algorithm using plain language with code-like keywords. It's not real programming — but it looks like it. That's why it's called "pseudo" (fake) code.

Pseudocode uses special words written in CAPITAL LETTERS to show important actions:

▶️

START / END

Mark the beginning and end of the algorithm.

📥

INPUT

Ask the user for information.

📤

PRINT

Show a result to the user.

🤔

IF / ELSE

Make a decision — do one thing or another.

Example — Check if a number is positive:

Pseudocode
START
  INPUT number
  IF number > 0 THEN
    PRINT "Positive"
  ELSE
    PRINT "Not positive"
  END IF
END
💡
Pseudocode is not tied to any programming language. You can translate it into Python, Java, C++, or any other language later. It focuses on the logic.

What is a Flowchart?

A flowchart is a picture of an algorithm. It uses special shapes connected by arrows to show the flow of steps.

Flowcharts are great because you can see the whole process at a glance.

The five key symbols of a flowchart:

Symbol Shape Name What It Means
🔵 Oval Start / End Where the algorithm begins or ends
🟦 Rectangle Process A step or action
🔷 Diamond Decision A yes/no question
🟨 Parallelogram Input / Output Data going in or coming out
➡️ Arrow Flow Direction — shows what comes next

Example Flowchart — Rain or Shine?

Here's a simple decision: "If it rains, take an umbrella; otherwise, wear a hat."

The flowchart would look like this:

  1. START (Oval)
  2. Is it raining? (Diamond — Decision)
  3. YES → Take an umbrella (Rectangle — Process)
  4. NO → Wear a hat (Rectangle — Process)
  5. END (Oval)

The same algorithm in pseudocode:

Pseudocode
START
  IF it is raining THEN
    take an umbrella
  ELSE
    wear a hat
  END IF
END
💡
Notice: Both formats describe the same algorithm. Pseudocode uses words; a flowchart uses shapes and arrows. Use whichever is clearer for your audience.

Guided Practice: Crossing the Road Safely

Let's write an algorithm for the task "Cross the road safely".

First, let's list the steps:

  1. Stop at the edge of the road.
  2. Look left.
  3. Look right.
  4. Look left again.
  5. If no cars, walk across.
  6. If cars, wait.

Now, as pseudocode:

Pseudocode
START
  STOP at road edge
  LOOK left
  LOOK right
  LOOK left again
  IF no cars THEN
    WALK across
  ELSE
    WAIT
  END IF
END

Which details did we ignore?

  • The color of cars
  • The number of people nearby
  • The weather (unless it affects safety)
💡
Abstraction in action: We focused only on the steps needed to cross safely. Everything else is non-essential.

  4. Any decisions that aren't in diamond shape.
  5. Any missing arrows or arrows going the wrong way.

Common mistakes to watch for:

  • Missing START or END
  • Decisions drawn in rectangles instead of diamonds
  • Arrows pointing in the wrong direction
  • Steps that are out of order
  • Missing a decision when one is needed

Key Takeaway

There are two powerful ways to write algorithms: pseudocode (plain language with code-like words) and flowcharts (pictures with special shapes). Both use abstraction — they show only the essential steps. Flowcharts use five symbols: oval for start/end, rectangle for process, diamond for decision, parallelogram for input/output, and arrows for direction.
