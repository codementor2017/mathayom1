Designing the Turf Algorithm

Quick Review from Lesson 7

In Lesson 7, we solved the turf problem in 5 steps:

  1. Convert units: 50 cm = 0.5 m
  2. Lawn area: 5 m × 4 m = 20 m²
  3. Piece area: 0.5 m × 0.5 m = 0.25 m²
  4. Divide: 20 ÷ 0.25 = 80 pieces
  5. Round up if needed (not needed here)
💡
Today's goal: Turn these 5 steps into a general algorithm that works for any lawn size — not just 5 m × 4 m. That's the power of abstraction!
Thinking in Variables

To make our algorithm work for any lawn, we need to use variables instead of fixed numbers.

What It Represents Fixed Value (Lesson 7) Variable (Lesson 8)
Lawn width 5 m width
Lawn length 4 m length
Turf piece size 0.5 m × 0.5 m 0.5 (constant)
Lawn area 20 m² lawn_area
Piece area 0.25 m² piece_area
Pieces needed 80 pieces
💡
Key idea: The variable width can be any number — 5, 6, 7, or 10. Our algorithm will work for all of them!

The Algorithm Steps (General Version)

Here's the algorithm written in plain language — for any lawn:

  1. Input the lawn width and length (in meters).
  2. Calculate the lawn area: lawn_area = width × length
  3. Calculate the piece area: piece_area = 0.5 × 0.5
  4. Calculate the number of pieces: pieces = lawn_area ÷ piece_area
  5. Round up to the nearest whole number.
  6. Output the number of pieces needed.
💡
Notice: The algorithm uses variables (like width) instead of fixed numbers. This is why it works for any lawn — that's the power of abstraction.
Writing the Pseudocode

Now let's write the algorithm in pseudocode. Remember the format from Lesson 5:

Pseudocode
START
  INPUT width, length
  lawn_area = width × length
  piece_area = 0.5 × 0.5
  pieces = lawn_area ÷ piece_area
  ROUND UP pieces
  PRINT pieces
END

Let's read through it:

  • START — begin the algorithm
  • INPUT width, length — ask the user for the lawn dimensions
  • lawn_area = width × length — compute the total lawn area
  • piece_area = 0.5 × 0.5 — compute the area of one turf piece
  • pieces = lawn_area ÷ piece_area — divide to find how many pieces
  • ROUND UP pieces — we can't buy partial pieces
  • PRINT pieces — output the answer
  • END — done!

Drawing the Flowchart

Now let's turn the pseudocode into a flowchart. Remember the 5 symbols from Lesson 5:

  • Oval — Start / End
  • Parallelogram — Input / Output
  • Rectangle — Process
  • Diamond — Decision
  • Arrow — Flow

Here's how our flowchart would look, step by step:

  1. START — Oval
  2. INPUT width, length — Parallelogram
  3. lawn_area = width × length — Rectangle
  4. piece_area = 0.5 × 0.5 — Rectangle
  5. pieces = lawn_area ÷ piece_area — Rectangle
  6. ROUND UP pieces — Rectangle
  7. PRINT pieces — Parallelogram
  8. END — Oval
💡
Notice: Our turf algorithm has no decision step. That's okay! Not every algorithm needs a diamond. The rounding step acts like a simple decision internally, but we don't need a diamond shape for it.

Testing the Algorithm with Different Inputs

A good algorithm works for many different inputs — not just one. Let's test our algorithm with two different lawn sizes:

Test 1 — Lawn 4 m × 3 m

  1. width = 4, length = 3
  2. lawn_area = 4 × 3 = 12 m²
  3. piece_area = 0.5 × 0.5 = 0.25 m²
  4. pieces = 12 ÷ 0.25 = 48
  5. ROUND UP = 48
  6. Output: 48 pieces

Test 2 — Lawn 6 m × 5 m

  1. width = 6, length = 5
  2. lawn_area = 6 × 5 = 30 m²
  3. piece_area = 0.5 × 0.5 = 0.25 m²
  4. pieces = 30 ÷ 0.25 = 120
  5. ROUND UP = 120
  6. Output: 120 pieces
💡
Great algorithms work for any input. Our algorithm gave correct answers for both 4 m × 3 m (48 pieces) and 6 m × 5 m (120 pieces).

Key Takeaway

A great algorithm works for any input, not just one specific case. By using variables instead of fixed numbers, our turf algorithm works for any lawn size. We write the algorithm in pseudocode for clarity, and draw a flowchart to visualize the flow. Always test your algorithm with different inputs to make sure it works. Next lesson, you'll learn about edge cases — special situations that can break an algorithm — and how to fix them.
